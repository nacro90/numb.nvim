1. Introduction                                *numb* *numb.nvim* *numb-intro*

numb.nvim peeks lines of the buffer in a non-obtrusive way. While you type an
Ex command that starts with a line number, such as `:15`, that line is
previewed in place: the view scrolls to it, 'number' and 'cursorline' are
turned on for the window, and folds are opened so the line is visible.

Nothing is committed until you confirm the command with <CR>. Aborting the
command line with <Esc> or <C-c> restores the window as it was, including the
original cursor position and the scroll position.

Absolute (`:15`), relative (`:+5`, `:-3`) and chained (`:++`, `:--`) targets
are all previewed, as are arithmetic combinations such as `:+2+3` and `:10-2`.
The Ex line symbols work as well: `:.` is the current line and `:$` the last
one, with arithmetic on either, as in `:.+5` and `:$-3`. See |:range| for the
addressing this follows.

A target past either end of the buffer is clamped to the first or the last
line. A command line that does not start with a line address, such as
`:write`, never triggers a peek.

Peeking is per window: the cursor, the window options and |w:numb_peeking|
belong to the window being peeked, so two splits showing the same buffer never
disturb each other's view, and a peek in a window that is not the current one
is restored independently.

The range highlight described under |numb-range_peek| is the one exception. A
highlight is attached to the buffer rather than to a window, so while you type
`:5,10d` in one split the range is visible in every split showing that buffer.

==============================================================================
2. Requirements                                            *numb-requirements*

Neovim 0.10 or newer. There are no other runtime dependencies; numb.nvim uses
nothing outside stock Neovim and Lua.

==============================================================================
3. Installation                                            *numb-installation*

numb.nvim calls |numb.setup()| itself from `plugin/numb.lua`, so the defaults
below are active as soon as the plugin is on your 'runtimepath'. Call
|numb.setup()| explicitly only when you want to change |numb-options|. To keep
the plugin from loading at all, see |g:loaded_numb|.

With lazy.nvim: >lua
    {
      'nacro90/numb.nvim',
    }

    -- or optionally pass `opts` to customize the config
    {
      'nacro90/numb.nvim',
      opts = {
        -- see |numb-options|
      },
    }
<
With `vim.pack` (built into Neovim 0.12): >lua
    vim.pack.add {
      'https://github.com/nacro90/numb.nvim',
    }
<
With Paq: >lua
    paq 'nacro90/numb.nvim'
<
With vim-plug: >vim
    Plug 'nacro90/numb.nvim'
<
With Packer (unmaintained; prefer lazy.nvim or `vim.pack`): >lua
    use 'nacro90/numb.nvim'
<

==============================================================================
4. Usage                                                          *numb-usage*

Nothing is needed to get the default behaviour. Type a line number on the Ex
command line and watch the buffer follow along: >
    :3
<
To change any of the |numb-options|, call |numb.setup()| from your
`init.lua`: >lua
    require('numb').setup {
      centered_peeking = false,
    }
<
From an `init.vim`, load it the same way through `:lua`: >vim
    :lua require('numb').setup()
<
Peeking can be turned on and off at runtime with the |:Numb| command or the
functions in |numb-api|.

==============================================================================
5. Command                                                      *numb-command*

                                                                       *:Numb*
:Numb [{action}]
                Control peeking at runtime. {action} is one of `enable`,
                `disable` or `toggle`, and defaults to `toggle` when omitted.
                Actions are completed with <Tab>.

                `enable` reinstalls the autocommands using the configuration
                that is already in effect, so options passed to a previous
                |numb.setup()| are preserved. An unknown {action} is reported
                through |vim.notify()| and nothing else happens.

==============================================================================
6. Options                                                      *numb-options*

Options are passed as a table to |numb.setup()| or |numb.enable()|. Every
option is a boolean. Any subset may be given; the rest keep their defaults.

Unknown option names, and values of the wrong type, are reported through
|vim.notify()| and ignored. Invalid configuration never raises: the offending
option keeps its default and the rest of the table is applied as usual, so a
typo cannot leave the plugin uninstalled.

Defaults: >lua
    require('numb').setup {
      show_numbers = true,
      show_cursorline = true,
      hide_relativenumbers = true,
      number_only = false,
      centered_peeking = true,
      range_peek = true,
      disable_for_buftype = {},
      disable_for_filetype = {},
    }
<
------------------------------------------------------------------------------
show_numbers                                               *numb-show_numbers*
                Type: `boolean`, default: `true`

                Set 'number' in the peeked window while peeking, so the line
                numbers are visible even in a window that normally hides
                them. The previous value is restored afterwards.

------------------------------------------------------------------------------
show_cursorline                                         *numb-show_cursorline*
                Type: `boolean`, default: `true`

                Set 'cursorline' in the peeked window while peeking, which
                highlights the previewed line. The previous value is restored
                afterwards.

------------------------------------------------------------------------------
hide_relativenumbers                               *numb-hide_relativenumbers*
                Type: `boolean`, default: `true`

                Turn 'relativenumber' off while peeking. With
                'relativenumber' on, the numbers shift as the previewed
                cursor moves, which makes the peeked line hard to identify.
                The previous value is restored afterwards.

------------------------------------------------------------------------------
number_only                                                 *numb-number_only*
                Type: `boolean`, default: `false`

                Peek only when the whole command line is a number expression,
                instead of whenever it starts with one. With this on, `:15`
                still peeks but `:15,20d` does not.

------------------------------------------------------------------------------
centered_peeking                                       *numb-centered_peeking*
                Type: `boolean`, default: `true`

                Center the peeked line in the window, as |zz| does. This also
                applies to the confirmed jump, so the line you land on stays
                where you saw it. Near the end of the buffer the window stays
                full rather than scrolling past the last line.

------------------------------------------------------------------------------
range_peek                                                   *numb-range_peek*
                Type: `boolean`, default: `true`

                Highlight the whole line range while you type `:N,M{cmd}`, so
                a destructive command such as `:50,80d` can be checked before
                it runs. Neovim previews |:substitute| through 'inccommand'
                but nothing else, so `:d`, `:y`, `:m`, `:t` and `:g` get no
                native preview at all.

                The lower bound is also previewed as an ordinary peek, so the
                start of the range is on screen. That is where `:d` leaves the
                cursor, but only `:d`: `:y` does not move the cursor at all,
                and `:m`, `:t` and `:s` finish near their destination.
                Reversed bounds are accepted: `:10,5` highlights 5 through 10.

                Endpoints may be numbers, `.`, `$`, or arithmetic on those, so
                `:.,+5`, `:10,+3` and `:30,$` all work. Ranges using marks or
                searches, `:'a,'b` and `:/pat/,/pat/`, are left to Vim and are
                not highlighted.

                Both Ex separators are understood. `,` counts an offset from
                the cursor, while `;` counts it from the address before it, so
                `:5;+3` is 5 through 8 where `:5,+3` from line 20 is 5 through
                23. When more than two addresses are given, Ex acts on the
                last two, so `:5,10,15d` highlights 10 through 15.

                The highlight belongs to the buffer, not to the window, so it
                shows up in every split displaying that buffer. The rest of
                the peek stays per window; see |numb-intro|.

                                                                  *NumbRange*
                The range highlight uses this group, linked to |hl-Visual| by
                default. Override it before or after `setup()`: >lua
                    vim.api.nvim_set_hl(0, "NumbRange", { bg = "#3a3a50" })
<
------------------------------------------------------------------------------
disable_for_buftype                                 *numb-disable_for_buftype*
                Type: `string[]`, default: `{}`

                'buftype' values to leave alone. A window whose buffer has one
                of these types is never peeked in: >lua
                    require('numb').setup {
                      disable_for_buftype = { "terminal", "quickfix" },
                    }
<
                Nothing is excluded by default, terminal buffers included.
                Vim performs `:15` in a terminal buffer exactly as it does
                anywhere else, so excluding one means accepting a jump that
                happens with nothing shown before it. Exclude a type when that
                trade is the one you want, not by habit.

                Compared against the whole value, so `""`, the 'buftype' of an
                ordinary file buffer, can be listed as well.

------------------------------------------------------------------------------
disable_for_filetype                               *numb-disable_for_filetype*
                Type: `string[]`, default: `{}`

                'filetype' values to leave alone, for buffers a plugin owns
                that carry no distinctive 'buftype': >lua
                    require('numb').setup {
                      disable_for_filetype = { "fugitive", "NvimTree" },
                    }
<
                Checked after |numb-disable_for_buftype|, and the same trade
                applies: the jump still happens, only the preview goes away.

7. Lua API                                                          *numb-api*

                                                                *numb.setup()*
numb.setup({opts})
                Apply {opts} (see |numb-options|) and install the
                autocommands and the |:Numb| command. Safe to call repeatedly;
                each call replaces the previous configuration and reinstalls
                the autocommands.

                `plugin/numb.lua` already calls this with no arguments, so
                calling it yourself is only needed to pass {opts}.

                Parameters: ~
                  • {opts} (`table?`) Options, see |numb-options|.

                                                               *numb.enable()*
numb.enable({opts})
                Install the autocommands again after |numb.disable()|. The
                configuration in effect is kept, so {opts} is optional; pass
                it to override options at the same time. Does nothing when
                peeking is already enabled.

                Parameters: ~
                  • {opts} (`table?`) Options, see |numb-options|.

                                                              *numb.disable()*
numb.disable()
                Remove the autocommands and drop all saved state. Any window
                that is peeking right now is restored first, including one
                opened through |numb.peek()|, whose handle becomes inactive
                and whose `User NumbUnpeek` fires. Peeking stays off until
                |numb.enable()| or |numb.setup()| is called again.

                A command line you already confirmed is the exception: its
                jump is made after the Ex command runs, and that still
                happens, with its `User NumbUnpeek`, when this is called in
                between, because the jump was asked for while peeking was on.

                Note that the |:Numb| command remains defined, so peeking can
                always be turned back on with `:Numb enable`.

                                                          *numb.get_config()*
numb.get_config()
                The configuration currently in effect, with the defaults of
                any option you did not set merged in. Useful for statusline
                components and other integrations that need to know how
                peeking is configured.

                The table is a copy, so changing it does not reconfigure the
                plugin; use |numb.setup()| or |numb.enable()| for that.

                Return: ~
                    (`table`) The active options, see |numb-options|.

                                                           *numb.is_enabled()*
numb.is_enabled()
                Reflects only what numb.nvim itself did. If something else
                clears the `numb` augroup, an `augroup numb | autocmd!` block
                in a user config for instance, peeking stops working while
                this still returns `true`. |numb-health| detects that case.

                Return: ~
                    (`boolean`) `true` while the autocommands are installed.

                                                           *numb.is_peeking()*
numb.is_peeking({winnr})
                Whether a peek is in progress in a window. Reads the same
                state as |w:numb_peeking|, so the two never disagree. An
                invalid window handle yields `false` rather than an error.

                Parameters: ~
                  • {winnr} (`integer?`) Window handle. `nil` or `0` means the
                    current window.

                Return: ~
                    (`boolean`) `true` while that window is peeking.

                                                                 *numb.peek()*
numb.peek({winnr}, {line}, {opts})
                Preview {line} in a window without moving there, exactly as
                the command line does, and return a handle that moves,
                accepts or cancels that preview. Meant for other plugins: a
                picker previewing its selection, or an LSP symbol list.

                The preview looks the same as one from the command line:
                |numb-show_numbers|, |numb-show_cursorline|,
                |numb-hide_relativenumbers| and |numb-centered_peeking| apply.
                |numb-disable_for_buftype| and |numb-disable_for_filetype| do
                not. They decide when the command line peeks on its own,
                while a caller here asked explicitly. Likewise
                |numb-range_peek| only gates the command line: an explicit
                {opts.range} is always highlighted.

                Only one peek is live at a time. Calling |numb.peek()| again
                ends the previous peek, and so does a command line once it
                addresses a line: typing `:12` takes the preview over, while
                `:w` or `:let` leaves it up. The handle that was superseded
                becomes inactive, see |NumbPeek:is_active()|.

                Ending the previous peek fires `User NumbUnpeek`, and a
                listener may open another peek from there, which is ended
                in turn. A listener that reopens every time is stopped after
                a few rounds: the peek it opened last is ended, and this
                call raises "a NumbUnpeek listener keeps reopening a peek",
                leaving no peek live.

                While peeking is disabled (|numb.disable()|, `:Numb disable`)
                nothing is previewed and the handle is inactive from the
                start, so a caller needs no check of its own. The same holds
                when a listener disables peeking while this call ends the
                previous peek, and for a call made while a peek is being
                shown, moved or put back, such as from an |OptionSet|
                autocommand that restoring a window option fires. Putting
                back includes landing on the target of an accepted peek, so
                a |WinEnter| autocommand the landing fires gets an inactive
                handle too.

                Parameters: ~
                  • {winnr} (`integer`) Window handle. `0` means the current
                    window. The window does not have to be the current one.
                  • {line} (`integer`) Line to preview, clamped to the first
                    or the last line of the buffer.
                  • {opts} (`table?`) Optional fields:
                    • {range} (`integer[]?`) A `{ first, last }` pair of line
                      numbers to highlight with |NumbRange| as well. Both
                      ends are clamped, and reversed bounds are accepted.

                Return: ~
                    (`NumbPeek`) The handle, with the methods below.

                Raises an error, through |error()|, when an argument has the
                wrong type, {winnr}, {line} or an end of {opts.range} is not
                an integer (`10.5`, NaN and `math.huge` are rejected), or
                {winnr} is not a valid window. These are programming
                mistakes, so they are not reported quietly, and nothing is
                peeked.

                Public since 1.3.0. The function, the handle methods and
                |NumbPeek-events| follow Semantic Versioning: a breaking
                change to any of them needs a new major version.

                                                           *NumbPeek:update()*
NumbPeek:update({line}, {opts})
                Move the preview to another line, in the same window. The
                window is restored first and peeked again, so what the
                final restore puts back is always the state from before the
                first peek. {opts.range} replaces the highlighted range, and
                leaving it out clears the range. Fires `User NumbPeek`.

                Parameters: ~
                  • {line} (`integer`) Line to preview, clamped as in
                    |numb.peek()|.
                  • {opts} (`table?`) As in |numb.peek()|.

                Return: ~
                    (`boolean`) `true` when the preview moved, `false` when
                    the handle is inactive, in which case nothing happens.
                    Bad arguments raise an error either way, before anything
                    changes, so the previous preview stays up.

                                                           *NumbPeek:accept()*
NumbPeek:accept()
                End the peek and stay on the previewed line. The jump
                happens immediately and is recorded in the jumplist, so
                |CTRL-O| returns to where the cursor was before the peek. The
                window options are restored, any fold around the line is
                opened, and the line is centered when
                |numb-centered_peeking| is on. Focus stays where it was:
                accepting a peek in another window does not switch to it.
                Fires `User NumbUnpeek` with `accepted = true`.

                Return: ~
                    (`boolean`) `true` when the peek was accepted, `false`
                    when the handle is inactive, in which case nothing
                    happens.

                                                           *NumbPeek:cancel()*
NumbPeek:cancel()
                End the peek and put the window back as it was: the cursor,
                the window options and the scroll position. Fires
                `User NumbUnpeek` with `accepted = false`.

                If the window was switched to another buffer during the
                peek, both this and |NumbPeek:accept()| only restore the
                window options: the saved positions belong to the old
                buffer, so the cursor stays where the switch put it.

                Return: ~
                    (`boolean`) `true` when the peek was cancelled, `false`
                    when the handle is inactive, in which case nothing
                    happens.

                                                        *NumbPeek:is_active()*
NumbPeek:is_active()
                Whether this handle is the live peek. A handle becomes
                inactive once it is accepted or cancelled, once another peek
                takes over, once |numb.disable()| is called, or once its
                window is closed. It never becomes active again: call
                |numb.peek()| for a new handle.

                Return: ~
                    (`boolean`) `true` while the handle is live.

                                                             *NumbPeek-events*
Every peek fires two |User| autocommands, whether it was opened through
|numb.peek()| or by typing on the command line. The details are in the
event's `data` field (see |nvim_create_autocmd()|).

  `User NumbPeek`    When a peek opens and on every update, after the
                     window shows the new line. Typing `:120` fires it once
                     per keystroke while the command line addresses a line.
  `User NumbUnpeek`  Once per peek, when it ends: accepted, cancelled,
                     taken over by another peek, ended by |numb.disable()|,
                     or its window closed. A takeover fires `NumbUnpeek` for
                     the old peek before `NumbPeek` for the new one. It
                     never fires twice for a peek, and fires exactly once
                     unless putting the window back or landing raises an
                     error. numb raises none there itself; one can only come
                     from an autocommand of yours that the restore or the
                     landing triggers, such as |WinEnter|, or through the
                     |:normal| the landing runs. That error propagates, and
                     the peek it hit fires no `NumbUnpeek`.

                     When the command line confirms a peek, the window is
                     put back at once, so the Ex command runs from where the
                     peek started, and `NumbUnpeek` fires only after the
                     command has run and the cursor has landed. A listener
                     therefore sees the buffer as the command left it, and a
                     peek it opens cannot change what the command acted on.
                     A peek opened in that window before then, such as by
                     the next command line of a mapping, makes the landing
                     and fires `NumbUnpeek` first, then shows itself. By
                     then the command has run, so each of two command lines
                     confirmed back to back keeps its jumplist entry, and
                     the new peek starts from where the first one landed.

`data` fields: ~
  • {win} (`integer`) Window handle of the peeked window: the one whose
    buffer is previewed and where accepting lands. |numb.is_peeking()| and
    |w:numb_peeking| describe the same window.
  • {line} (`integer`) The previewed line, after clamping.
  • {range} (`integer[]?`) The highlighted range as `{ low, high }`, or `nil`
    when there is none.
  • {accepted} (`boolean`) `NumbUnpeek` only: `true` when the peek ended
    through |NumbPeek:accept()| or a confirmed command line, `false` for
    every other way it can end. It stays `true` when the window had been
    switched to another buffer and so did not move.

Reacting to a confirmed jump: >lua
    vim.api.nvim_create_autocmd('User', {
      pattern = 'NumbUnpeek',
      callback = function(args)
        if args.data.accepted then
          print(('landed on line %d'):format(args.data.line))
        end
      end,
    })
<
                                                             *numb-api-picker*
A picker previewing its selection: peek when the selection first lands on a
line, move the same handle as it changes, accept on confirm, cancel on close.
Since |NumbPeek:update()| returns `false` for a handle that has gone
inactive, the picker opens a new peek whenever that happens: >lua
    local numb = require('numb')
    local preview

    local function on_selection_changed(win, line)
      if not (preview and preview:update(line)) then
        preview = numb.peek(win, line)
      end
    end

    local function on_confirm()
      if preview then preview:accept() end
      preview = nil
    end

    local function on_close()
      if preview then preview:cancel() end
      preview = nil
    end
<

8. Statusline integration                                    *numb-statusline*

                                                              *w:numb_peeking*
w:numb_peeking  Set to `true` in a window while that window is peeking, and
                back to `nil` as soon as the peek ends, whether it was
                confirmed or aborted. The scope is the window, not the buffer,
                so two splits showing the same buffer never cross-flag each
                other. Read it from Lua as `vim.w.numb_peeking`.

A minimal lualine component reading the flag: >lua
    require('lualine').setup {
      sections = {
        lualine_x = {
          function() return vim.w.numb_peeking and 'peek' or '' end,
        },
      },
    }
<
From Lua, |numb.is_peeking()| answers the same question for any window.

9. Health check                                                  *numb-health*

`:checkhealth numb` reports whether numb.nvim is installed and set up the way
you think it is. It covers:

  - the running Neovim version against the supported floor;
  - where numb.nvim was loaded from, and whether more than one copy sits on
    the 'runtimepath', which is the usual reason a configuration change seems
    to do nothing;
  - whether |numb.setup()| has run, and whether peeking is enabled or was
    turned off with `:Numb disable`;
  - whether the `numb` augroup still owns its |CmdlineChanged| and
    |CmdlineLeave| autocommands, which another `augroup numb` in your config
    can clear;
  - which windows are peeking at the moment, and any saved state left behind
    by a window that was closed mid-peek;
  - the active configuration, so that a pasted health report is
    self-contained.

See |health| for `:checkhealth` itself.

==============================================================================
10. Turning peeking off                                       *numb-disabling*

At runtime, use `:Numb disable` (see |:Numb|) or |numb.disable()|. The options
you configured are kept, so `:Numb enable` resumes with them.

                                                               *g:loaded_numb*
g:loaded_numb   Set this before startup to keep numb.nvim from loading at
                all: >lua
    vim.g.loaded_numb = 1
<
                `plugin/numb.lua` returns early when the variable is set, so
                no autocommands and no |:Numb| command are created. The
                variable is set to `1` by the plugin itself once it has
                loaded, which also makes loading idempotent.
